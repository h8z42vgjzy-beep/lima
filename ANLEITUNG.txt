Feindschaft – Chat-Reparatur 2 mit automatischer Aktivierung

Warum diese Fassung:
Die alte Fehlermeldung 'Zwischen euch gibt es bereits eine Anfrage' steht nur
in der ursprünglichen Anfragefunktion. Das vorige Paket musste zusätzlich
über den Render-Build aktiviert werden. Diese Fassung aktiviert sich beim
Installieren UND bei jedem normalen Start über yarn start / npm start.

HOCHLADEN
1. ZIP entpacken.
2. Diese DREI Dateien im bestehenden GitHub-Repository ins Hauptverzeichnis
   neben server.mjs hochladen:
     package.json
     apply-chat-repair.mjs
     chat-repair.mjs
   Vorhandene gleichnamige Dateien ersetzen und den Commit speichern.
   Bitte die ZIP nicht einfach als ZIP hochladen.
3. In Render den vorhandenen Service lima öffnen und das neueste Commit
   deployen. Falls kein Auto-Deploy startet: Manual Deploy -> Deploy latest commit.
4. Build Command kann 'yarn' sein. Ein vorheriger Befehl
   'node apply-chat-repair.mjs && yarn' funktioniert ebenfalls.
   Start Command muss 'yarn start' oder 'npm start' sein.
   Falls dort ausdrücklich 'node server.mjs' steht, ändere ihn auf 'yarn start'.
5. Im Start-Log muss diese Zeile stehen:
     CHAT-REPAIR-2 AKTIV – Status: /api/chat-repair-status
6. Erst nach 'Your service is live' alle alten App-Fenster und Browser-Tabs
   schließen und die Website neu öffnen.

AKTIVIERUNG OHNE ANMELDUNG PRÜFEN
Diese Adresse in einem neuen Tab öffnen:
https://lima-te6q.onrender.com/api/chat-repair-status

Es muss diese Antwort erscheinen:
{"active":true,"repair":"chat-repair-2","version":2}

Wenn eine Fehlermeldung, 'Nicht gefunden' oder die normale Startseite erscheint,
ist diese Reparatur dort noch nicht aktiv. Dann nicht erneut Punkte für Anfragen
riskieren, sondern den neuen Render-Deploy/Start-Log prüfen. Ein erfolgreiches
Hochladen bei GitHub alleine beweist noch nicht, welcher Code auf Render läuft.

Zusätzlich steht in der Chat-Übersicht: 'Chat-Reparatur 2 aktiv'. Wenn die
Statusadresse korrekt antwortet, dieser Hinweis aber fehlt, sind noch alte
Oberflächendateien geöffnet: alle Tabs/Apps schließen und neu öffnen.

BESTEHENDEN CHAT WIEDERHERSTELLEN
1. Beide Personen prüfen im Profil, ob sie einander noch blockiert haben,
   und heben ihre jeweilige Blockierung auf.
2. Eine Person öffnet die Chat-Übersicht und drückt beim alten/abgelehnten Chat
   'Erneut anfragen · kostenlos'. Keine erneuten 200 Beleidigungen.
3. Die andere Person öffnet die Chat-Übersicht und nimmt die Anfrage an.
   Die offene Übersicht aktualisiert sich spätestens nach ca. 10 Sekunden.
4. Danach sind Verlauf und Schreiben wieder erreichbar. Texte lesen kostet
   nichts; eine neue Textnachricht senden kostet weiterhin 5 Beleidigungen.

NEUE BLOCKIERUNGEN
Sie sperren den Zugriff, ohne eine bestehende Zustimmung dauerhaft zu
überschreiben. Nach Entblockieren ist ein angenommener Chat wieder nutzbar,
solange die andere Person nicht weiterhin blockiert. Alte abgelehnte Datensätze
werden aus Sicherheitsgründen erst durch die erneute Annahme freigegeben.
Doppelte Anfragen kosten nicht nochmals. Nach einer weiteren Ablehnung kann
frühestens nach sieben Tagen erneut kostenlos angefragt werden.

Dieses Paket enthält weder Nutzerdaten noch eine Ersatzdatenbank. Es verändert
keine Disk-Einstellungen. Frühere Abbuchungen werden nicht nachträglich verändert.
Die vorhandene Website wird gezielt beim Start angepasst. Bei unbekanntem
Quellcode bricht die Aktivierung vor Änderungen mit einer verständlichen Meldung
ab. Das kann nur anhand des tatsächlichen Start-Logs geprüft werden.

PRÜFUNG
Fünf gezielte automatisierte Tests bestanden:
- Start über npm start mit der alten ungepatchten Website, ohne extra Build-Befehl,
  danach Statusantwort, ausgelieferter Oberflächenhinweis und ankommende Anfrage.
- Upgrade von Reparatur 1; flacher GitHub-Upload; wiederholte Ausführung;
  unbekannte Quelldateien werden nicht überschrieben.
- Blockieren, Entblockieren, gegenseitige Blockierung und vorhandener Verlauf.
- Kostenlose Wiederanfrage alter Chats mit richtiger empfangender Person und
  nötiger Zustimmung; fremde Konten erhalten keinen Zugriff.
- Erste Anfrage kostet einmal 200, weitere Wiederholungen nichts; Sieben-Tage-Pause.

Diese Tests liefen in einer isolierten lokalen Umgebung. Der echte Render-Deploy
und deine Konten wurden nicht aus der Ferne geprüft. Dafür ist die Statusadresse da.
